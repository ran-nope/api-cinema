# API Cinema design decisions

The interface should feel like a small cinema editing desk built to teach HTTP.

- Warm paper frames the tool; ink is reserved for returned data. Rust orange identifies the primary action and request animation. Muted green belongs to demo context and successful results.
- Copy names the task: send, inspect, repair. Avoid vague slogans, invented credibility claims, badges without meaning, or decorative metrics.
- The scene library and guided practice share a narrow rail. On desktop, the response monitor receives most of the workbench width and the request storyboard occupies a narrow column beside it.
- Georgia brings an editorial voice to the title and reading notes. Arial provides compact controls. Monospace is for code, methods, status codes, and small navigational labels.
- Square rules and a few small corner radii establish hierarchy. No gradients, glow decorations, repeating shadow cards, or full-page dark dashboard treatment.
- On phones, show the current scene with an explicit scene switcher. Keep challenge choices in a compact horizontal list. Return the storyboard to a horizontal diagram above the response.
- Provide visible focus, understandable loading and error states, real empty states, and reduced-motion behavior. Never convey request success only with color.
- Preserve request mechanics, challenge validation, and truthful explanations of locally handled demo calls.
